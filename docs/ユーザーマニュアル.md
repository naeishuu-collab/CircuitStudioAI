# CircuitStudio AI ユーザーマニュアル

## 1. できることと必要なソフト

CircuitStudioはCircuitDSLを検査し、KiCad回路図、BOM、ERC/ネットリスト/SVGを作ります。PCB条件をDSLに明記した場合は、限定的な2層基板を作ってDRCを実行します。R/Cを明示した一部の過渡解析はngspice 47で実行できます。

- **通常起動**: Windows 64-bitとmacOS 15 runner向け配布を用意します。Windows版はPython不要、macOS版もPython/Tkを含むアプリです。ソース版はPython 3.10以上とTkを使います。
- **KiCad**: 回路図/PCBのCLI検査、標準ライブラリ解決に必要です。KiCad本体は別途インストールします。Windows実機はKiCad 10.0.7で検証済みです。macOSはCIでCLIを検査し、物理Mac GUIは未確認です。
- **SPICE**: Windows版には配布物に含めたngspice 47を使えます。macOSはネイティブngspiceを別途用意し、PATHまたは`NGSPICE`で指定します。Windows実行ファイルはmacOSでは利用しません。
- **AI**: 任意です。AIボタンを使わなければAPIキー、インターネット、課金は不要です。

## 2. 起動と終了

### 配布版

1. `dist/CircuitStudioAI/`フォルダーを任意の場所へコピーします。中のファイル構成は崩さないでください。
2. `CircuitStudioAI.exe`をダブルクリックします。
3. KiCad連携を使う場合はKiCad 10を別途インストールしてください。KiCad本体は配布版に含まれません。

### ソース版

PowerShellでプロジェクトルートを開き、`.\run.bat`、または `py -3 app.py` を実行します。

macOSではターミナルでプロジェクトルートを開き、Python 3.11とTkがある環境から次のように起動します。

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

### EXEのビルド

Python 3.11をインストールしたWindowsで`build-windows.bat`を実行します。PyInstallerは一時フォルダーに隔離して入れます。成功後は `dist/CircuitStudioAI/CircuitStudioAI.exe` ができます。KiCadは同梱されません。`tools/ngspice-47`がプロジェクト内にある場合、その実行ファイルとライセンスも配布フォルダーへコピーします。

### macOSアプリのビルド

Apple SiliconとIntelは各アーキテクチャのMac runner上で個別にビルドします。配布前のCI成果物はGitHub ActionsのCross-platform CIからダウンロードできます。DMG/ZIPは未署名・未公証です。初回起動ではINSTALL.mdのGatekeeper手順を読み、配布元とSHA-256を確認してください。

## 3. 最初にLEDサンプルを出力する

1. CircuitStudioを起動し、**DSLを開く**を押して `samples/led_v2.circuit.yaml` を選びます。
2. エディターにJSON形式のCircuitDSLが表示されます。この形式はYAML 1.2としても有効です。部品値やネットを編集する場合は、引用符・カンマ・波括弧を壊さないようにしてください。
3. **検証してKiCad出力**を押し、出力先の親フォルダーを選びます。
4. DSLの`project.name`と同じ名前のサブフォルダーにKiCadプロジェクト、回路図、BOM、SVG、ネットリスト、診断結果、PCB/DRC結果が出ます。
5. 下部の履歴でDSL診断、KiCad ERC、ネットリスト/SVG、PCB DRC、製造判定を確認します。ERC/DRCのPASSだけで電気安全や製造可能とは判定しません。
6. **KiCad起動**を押し、生成した `.kicad_pro` または `.kicad_sch` を選んでKiCadで開きます。回路図と基板を編集して保存できます。KiCad 10.0.7での確認では、回路図の初回保存時に旧形式からの変換通知が出ました。保存前にプロジェクトフォルダーを複製しておけば元の生成物を保護できます。

出力先に同名プロジェクトがあり、フォルダー内が空でない場合は上書きを拒否します。再コンパイルするときは新しい空の出力先を使うか、既存成果物をユーザー自身で退避してください。

## 4. 画面のボタン

| ボタン | 使い方 |
|---|---|
| **AIからDSL案** | 上の「日本語の設計指示」に入力して押します。AIの返答をDSLスキーマ検証し、DSL欄に置きます。KiCad出力は自動実行しません。API未設定なら手動DSLを使ってください。 |
| **DSLを開く** | `.circuit.yaml`、`.yaml`、`.json`を開きます。読み込み時に構文/スキーマを検査します。 |
| **サンプル** | `samples`フォルダーからサンプルDSLを選びます。 |
| **DSL保存** | 編集したDSLを保存します。既存先は確認を出し、既存バックアップ `.bak` もある場合は上書きしません。 |
| **検証してKiCad出力** | DSLを解析し、FAILがなければ新規プロジェクトを生成します。KiCad CLIがあればERC、ネットリスト、SVG、PCB DRCも実行します。 |
| **回路図/ERC** | 既存 `.kicad_sch` を選び、KiCad CLIでERCを実行します。KiCad GUIを開く操作は「KiCad起動」です。 |
| **既存PCB評価** | 既存 `.kicad_pcb` を読み取り、構造情報とKiCad CLI DRCを表示します。元基板は変更しません。必要なら新しいJSONレポートを保存します。 |
| **SPICE実行** | `.cir` / `.sp`を選んでngspiceを実行します。実行ログとCSV出力先を表示します。 |
| **KiCad起動** | KiCadプロジェクト、回路図、基板ファイルを選んでKiCadを起動します。 |

長い処理はバックグラウンドで実行されます。実行中はボタンが無効になります。完了後、診断履歴またはエラーダイアログを確認してください。

## 5. CircuitDSLの編集

DSL v1/v2の仕様は [`CircuitDSL.md`](CircuitDSL.md)、[`CircuitDSL-v2.md`](CircuitDSL-v2.md)、スキーマは `schemas/` にあります。v1の読み込みは維持されています。v2へ移行する場合は、まず元ファイルを別名保存してください。

- 部品は`components`に参照番号、カタログsymbol ID、値、ピン番号→ネット名を記述します。
- `nets`に全ネット名と`signal`/`power`/`ground`の種別を宣言します。
- カタログにないシンボル・ピン・実部品型番を自動で推測しません。カタログ一覧は `circuitstudio/catalog.py` です。
- `design.unknowns`に未確定条件を残せます。UNKNOWNはFAILではありませんが、設計承認を意味しません。
- PCBを出すには、v2で層数、板厚、外形、クリアランス、配線幅、全フットプリント、全配置、明示配線が必要です。自動配線やGNDゾーンはありません。

## 6. RCのSPICE過渡解析

1. `samples/rc_filter_spice_v2.circuit.yaml`を開きます。
2. **検証してKiCad出力**を押し、新しい空の出力先を選びます。
3. 生成されたプロジェクトフォルダー内の `RC_Filter_SPICE.cir` を**SPICE実行**から選びます。
4. SPICE欄に`PASS`と表示され、実波形CSVの保存先が表示されたことを確認します。

回路・条件・理想モデルはDSLの`simulation`に明記されています。生成デッキは抵抗・コンデンサ、PULSE電圧源、指定された観測ネットだけです。RCサンプルではngspice 47が過渡解析CSVを実際に生成したことを確認しています。既存の `samples/RC_Filter_SPICE/transient.csv` は実行結果の見本なので、同じデッキを選ぶと上書き防止のためBLOCKEDになります。繰り返し実行する場合は新しいプロジェクト出力を作ってください。

既存のSPICEネットリストも実行できますが、外部モデルは選択したネットリストのフォルダー内に置いてください。制御コマンドは安全確認のため許可リスト方式です。未対応コマンドを使うデッキはBLOCKEDとなります。解析のPASSはモデル内の数値計算成功であり、実機動作の保証ではありません。

## 7. AI連携（任意）

AIボタンはOpenAI互換の `/chat/completions` を1回呼び出します。既定URLはOpenAI API、既定モデル名は `gpt-4o-mini` です。URL、モデル、キーは起動前に `CIRCUITSTUDIO_API_BASE`、`CIRCUITSTUDIO_MODEL`、`OPENAI_API_KEY` 環境変数で設定します。遠隔HTTPにキーを送る設定は拒否し、遠隔接続はHTTPSが必要です。API側の利用料金・データ送信は各Providerの条件に従うため、利用者が設定・確認してください。キーはDSLやログに保存しません。

AIの出力は提案です。受け取ったDSLがスキーマ/意味検査に通っても正しい回路とは限りません。部品型番、データシート、電源条件を確認してからKiCadを生成してください。自動修正や差分ロールバックは未実装です。

## 8. Hブリッジの扱い

`samples/hbridge_incomplete.circuit.yaml`は意図的に出力をBLOCKEDにします。少なくとも、モーターの定格電圧・連続電流・停止電流、駆動方式、ゲートドライバとハイサイド条件、デッドタイム、保護、電源過渡、部品定格、熱条件が確定するまで完成回路として使わないでください。RP2040の3.3V GPIOだけで12Vモーターを安全に駆動できると推定しません。

## 9. 判定状態の読み方

- **PASS**: 指定された検査条件を満たしました。範囲外の安全性まで証明しません。
- **WARNING**: 注意事項・例外があります。根拠と修正案を読んでください。
- **FAIL**: 構造または指定制約に違反します。KiCad生成を止める場合があります。
- **UNKNOWN**: 部品情報、定格、運転条件などが不足し、判定できません。
- **BLOCKED**: 入力不足、非対応構成、安全上の理由などで処理を止めました。
- **NOT_EXECUTED**: 対応ツールがない、または対象外で実行していません。

PCBの製造判定は、DRCがPASSでも電流容量・温度上昇・熱・組立条件が未検証なら `NOT_PROVEN` です。

## 10. トラブルシューティングと既知の制限

- **KiCadが見つからない**: KiCad 10をインストールしてください。WindowsはPATH/登録先を、macOSはKiCad.app内のkicad-cliを探索します。別の場所にある場合は`KICAD_CLI`にCLIのフルパスを指定します。
- **EXEが起動しない**: `dist/CircuitStudioAI/`内のファイルをまとめて保持し、Windows Defenderの警告内容とエラーを確認してください。単体EXEだけ抜き出して起動しないでください。
- **ngspiceが見つからない**: Windows配布版では`tools/ngspice-47/bin/ngspice.exe`、macOSではネイティブngspiceをPATHまたは`NGSPICE`に指定します。macOSアプリにはngspiceを同梱しません。
- **YAML構文エラー**: 標準ライブラリのみではJSON部分集合を使います。通常のYAML構文にはPyYAMLが必要です。JSONサンプルは追加依存なしで開けます。
- **PCB生成BLOCKED**: 全部品の標準フットプリント、配置、2層、板厚、外形、クリアランス/幅、明示ルートが必要です。オートルート、ゾーン、取付穴、裏面配置、3Dは未対応です。
- **macOSでPCB生成がNOT_EXECUTED**: KiCad同梱のpcbnewとABI互換性を推測しません。KiCadと同じ版を返すPythonのパスを`KICAD_PYTHON`に設定してアプリをターミナルから起動してください。版が一致しない場合は実行しません。
- **部品/ピンUNKNOWNまたはFAIL**: `circuitstudio/catalog.py`とデータシートの端子番号を照合します。型番からの自動補完はしません。
- **KiCad IPC**: KiCad 10のIPCは起動中GUIに接続するPCBエディター向けです。CircuitStudioのIPC操作はありません。CLIとネイティブファイル生成を使ってください。
- **15部品を超える回路図**: 現行は単一A3シート15部品までで、階層シート/自動ページ分割は未実装です。
- **GUI保存/再読込**: KiCad 10.0.7でLED回路図/PCBの隔離コピーを開いて保存・終了・再読込し、その後ERC/DRC 0件を確認済みです。任意のユーザー回路図やPCB、PCB 3D表示は未検証です。重要な既存ファイルは複製後に作業してください。

## 11. 主なファイル

- `app.py`, `run.bat`: ソース版起動
- `build-windows.bat`, `CircuitStudioAI.spec`, `requirements-build.txt`: Windows EXEビルド
- `scripts/build_macos.sh`, `.github/workflows/cross-platform.yml`: macOSパッケージとクロスプラットフォームCI
- `circuitstudio/`: parser、診断、KiCad、PCB、SPICE、Provider、GUI
- `schemas/`: CircuitDSL v1/v2 JSON Schema
- `samples/`: LED/RC/MOSFET/Hブリッジ例。`LED_Indicator_v2/`はKiCad 10 GUIで保存/再読込したプロジェクト、`RC_Filter_SPICE`は検証済み回路図とCSV出力を含む
- `reports/kicad10-environment-audit.md`, `reports/test-results.md`: 実測環境とテスト記録
- `THIRD_PARTY_NOTICES.md`: PyInstaller/ngspice/KiCadの配布境界とライセンス情報
